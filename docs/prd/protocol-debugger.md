# 协议检查器

## 定位

协议检查器是仅在调试构建中开放的独立只读窗口，用于观察应用与 app-server 之间实际经过本机 stdio 或远程 WebSocket 传输的 JSON-RPC 消息

协议检查器不创建 app-server 会话，不发送协议消息，不绑定服务器或会话，也不参与业务窗口的连接引用和窗口状态持久化

## 打开方式

- 设置中的开发者分区提供打开协议检查器入口
- `Ctrl+Shift+D` 打开协议检查器
- 同一应用进程只保留一个协议检查器窗口，重复打开时激活已有窗口
- 正式构建不展示入口且拒绝创建或订阅协议检查器

## 采集范围

- 记录实际尝试写入 app-server 的客户端请求、通知和服务端请求响应
- 记录从 app-server 收到的服务端响应、通知和服务端请求
- 连接测试产生的 app-server 初始化消息与已配置连接分开标识
- 多个业务窗口共享物理连接时，每条线级消息只记录一次
- 响应按物理连接和请求 ID 关联请求方法、来源窗口和往返耗时

共享连接层抑制或在客户端合成且未进入实际传输的消息不作为线级消息展示

## 数据安全

- 只有协议检查器成功订阅后才开始解析和缓存消息
- 认证令牌、密码、Cookie、认证头、私钥和通用 secret 字段在进入缓存前递归脱敏
- 界面明确提示追踪内容仍可能包含提示词、代码、文件路径和工具输出
- 追踪只保存在内存中，不写数据库或日志，关闭窗口后立即清空
- 复制操作仅复制已经脱敏且可能被截断的展示内容

## 容量与故障隔离

- 单条展示内容上限为 1 MiB，超过后保留消息元数据并标记内容已截断
- 缓存同时受 5000 条和 32 MiB 上限约束，达到任一上限时淘汰最旧记录并显示累计数量
- 追踪消息按短时间窗口批量推送，列表使用虚拟滚动
- 追踪订阅失败、事件投递失败、缓存淘汰或窗口销毁不得改变真实协议收发和连接生命周期

## 界面

顶部提供服务器、方向、消息类型、来源和全文搜索过滤器，并提供暂停跟随与清空操作

左侧时间线展示时间、方向、类型、方法和耗时，右侧展示服务器、物理连接、来源窗口、传输路径、请求 ID、消息大小和格式化 JSON

常态方向和消息类型使用低强调样式，入站方向可使用链接色辅助区分，只有采集错误使用错误状态色
